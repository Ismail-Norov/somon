# Тестовые сценарии

1. Регистрация и вход пользователя.
2. Студент открывает `/admin/dashboard` — редирект / нет доступа к данным API.
3. Преподаватель видит только свои группы.
4. Админ создаёт курс.
5. Админ создаёт группу и назначает преподавателя.
6. Админ добавляет студента в группу.
7. Админ/преподаватель создаёт занятие (конфликт расписания блокируется).
8. Преподаватель отмечает посещаемость.
9. Преподаватель создаёт задание — студенты получают уведомление.
10. Студент отправляет ответ.
11. Преподаватель выставляет оценку — уведомление студенту.
12. Прогресс студента пересчитывается.
13. Изменение расписания создаёт уведомление.
14. Поиск пользователей/курсов работает.
15. Адаптив: боковое меню сворачивается на узком экране.
16. Пустые списки показывают Empty State.
17. Онлайн-занятие требует http(s)-ссылку, офлайн — филиал и аудиторию.
18. Преподаватель добавляет материал с файлом и видео — студент открывает и скачивает файл.
19. Студент отправляет ответ текстом и файлом — работа появляется «На проверке», файл скачивается.
20. Оценка с комментарием видна студенту, в истории активности есть записи.
21. Студент подаёт заявку на курс — админ одобряет только с выбором группы этого курса.
22. Материал сайта с доступом «только курс» виден в библиотеке только студентам курса и скрыт на сайте.
23. Черновик новости не виден на сайте; после публикации — виден.
24. Настройки сайта сразу отражаются на публичных страницах.
25. Нельзя удалить пользователя с учебными данными (409) и самого себя; вместо удаления — блокировка/архив.
26. Смена пароля: неверный текущий пароль отклоняется, после смены работает только новый пароль.
27. Студент/преподаватель не имеют доступа к админским API (403).
